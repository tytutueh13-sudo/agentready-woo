04 Evidence boundary

What crosses the boundary—and what never does.

The connected Release Gate accepts a narrow, documented aggregate contract. It does not need customer identity, order contents or payment credentials.

Allowed evidence

  • WooCommerce and WordPress version identifiers
  • Aggregate product and endpoint counts
  • Boolean capability and configuration checks
  • Timestamp, run identity and cryptographic signature

Evidence is bound to an owned store and a finite release run.

Rejected data

  • Customer names, emails or addresses
  • Order line items or payment credentials
  • WordPress administrator passwords
  • Private product descriptions or uploaded documents

The free preflight reads only public web surfaces.

06 Questions

Before you run it

Does a public preflight certify my store?

No. It reports the selected public surfaces at the observation time. It does not certify future availability, discoverability or checkout success.

Why can a result be BLOCKED or UNMEASURED?

A store may reject automated access, expose an unsupported response, time out or leave a protocol undeclared. AgentReady records that uncertainty instead of converting it into a failure.

Does Release Gate create a test order?

No. The root Release Gate contract does not create orders, reserve inventory, handle payment credentials or send customer email.

Is the Release Gate available for purchase?

Not yet. The public preflight is free; Release Gate settlement remains disabled while owner-authorized evidence and usage invariants are measured.

Looking for catalog, offer and cart-handoff tools? Those connected-store commerce capabilities are a separate product surface, not Release Gate evidence.
